# Change Manifest — JOINT-3A — Per-Class Dashboard & Trend Participant Partition

## Read-path classification

- `AcademicRoleDashboardService`: institutional/Waka dashboard aggregates all canonical participants once per `ClassSession`; Wali dashboard read paths now partition joint participants by authorized class.
- `AttendanceSemanticMetricsService`: class-period metrics reuse the canonical joint roster attribution helper for joint sessions.
- `JointAttendanceRosterBreakdownService`: owns the shared effective enrollment attribution and excludes zero/multiple valid enrollment matches from a class partition.
- `SessionSemanticMetricsService`: session discovery/count semantics remain unchanged; class-scoped session counts remain one per participating class and institutional aggregation remains distinct by class-item contract.
- `WaliKelasContextResolver`: inspected for authorization coupling and unchanged.
- Dashboard controller/Blade, `AcademicTodaySessionService`, and monthly-report paths: unchanged.

## Canonical participant partition

- Snapshot rows remain the authority for who participated.
- For a joint session, a participant is included in a target class only when exactly one active `StudentClassEnrollment` matches an effective session-scope class at the session date.
- A participant with no match or multiple matches is excluded from class-specific metrics and is never silently assigned to the anchor class.
- Ordinary single-scope sessions retain existing behavior and their participant snapshot is not globally filtered.

## Metric behavior

- Institutional Waka/Super metrics continue using the complete canonical joint snapshot once: 2B=10 and 3B=20 contribute 30 opportunities, not duplicated session passes.
- Wali/class-scoped trend, operational attendance-session roster, physical presence, and completeness use only participants attributable to the authorized class set.
- Physical presence remains `(PRESENT + LATE) / RESOLVED`; completeness remains `RESOLVED / ELIGIBLE`.
- Historical enrollment is evaluated at `ClassSession.planned_start_at` date.
- Class monitoring and session-count contracts are preserved; no dashboard UI redesign was made.

## Authorization and frozen areas

- No Wali mutation privilege changed.
- WAKA-2 `AcademicTodaySessionService` unchanged.
- Monthly reports and exports/imports unchanged.
- No attendance facts, migration, schema, database write, seed, import, RBAC, or historical rewrite.
