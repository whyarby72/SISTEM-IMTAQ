## Scope and lineage

The preceding SOC-I1A pilot attempt failed safely with PostgreSQL SQLSTATE 42830 while creating `session_occurrence_versions_supersedes_version_id_foreign`. The failed migration was automatically rolled back; pilot remained at 41 applied migrations with no occurrence table and no effective pointer column. This manifest supersedes no business behavior and explicitly preserves that failed-attempt evidence.

## Root cause

The failed migration attempted a scalar relationship `FOREIGN KEY (supersedes_version_id) REFERENCES session_occurrence_versions(id)`. PostgreSQL reported no matching unique candidate for the referenced definition in the migration path. Independently of that failure, the scalar FK could not enforce the required same-ClassSession invariant. The required candidate key is `UNIQUE (class_session_id, id)`.

## Repair

The migration now creates `supersedes_version_id` as a nullable UUID, creates the composite candidate key with the base table, and then adds:

`FOREIGN KEY (class_session_id, supersedes_version_id) REFERENCES session_occurrence_versions(class_session_id, id) ON DELETE RESTRICT`.

The existing effective pointer remains nullable and is enforced by:

`FOREIGN KEY (id, effective_occurrence_version_id) REFERENCES session_occurrence_versions(class_session_id, id) ON DELETE RESTRICT`.

Down order removes the effective pointer FK/column, removes the supersedes FK, then drops the occurrence table. No write service, controller, route, UI, status remapping, denominator cutover, eligibility activation, source authority, or historical backfill was added.
