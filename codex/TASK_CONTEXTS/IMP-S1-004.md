# TASK CONTEXT — IMP-S1-004

## Outcome

Implement effective-dated Student lifecycle status history with overlap prevention.

## Scope

One row represents one effective status interval for one Student. Intervals use `[effective_from, effective_until)`; a null end is open-ended.

### Allowed now

- `student_status_history` migration and Shared Core model;
- candidate lifecycle statuses, effective dates, decision/reason, actor reference and versioning;
- database/model overlap tests and local PostgreSQL verification;
- task/change records required by safe maintenance.

### Not allowed now

- append-only audit logs/correction requests;
- Academic enrollment, class, schedule or attendance features;
- Guardian, RBAC/auth, provider, staging or production implementation;
- inventing institutional status vocabulary beyond the documented candidate set.
